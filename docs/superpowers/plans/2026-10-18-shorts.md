# Formula Shorts: narrated vertical videos of any formula

> Built inline in the main thread (user preference: no background subagents). The first step copies
> this plan to `docs/superpowers/plans/2026-10-18-shorts.md` on the branch. Steps use `- [ ]`.
> TDD per step: write the failing test, make it pass, run the gate.

## Context

Formula has 39 tools, each with a rich `assets/content/<id>/doc.md`, and `tools/capture` already
renders every tool headlessly (egui_kittest + wgpu) at exact pixel sizes and pipes frames to ffmpeg
for the README GIFs. Nothing turns a tool into a shareable video: no vertical format, no on-screen
text, no narration. The user wants a pipeline that takes a tool id plus a few notes and produces a
finished YouTube/Instagram Short (exact 1080×1920, title, equation, captions, spoken narration), plus
a Claude Code skill so "make a short about Lorenz" does all of it, and an output folder that keeps
every generated asset by name and date.

**Branch:** `feat/shorts`, from updated `main`. One PR. The user reviews and merges.

**User decisions (2026-10-18):**
- All three voice providers: Microsoft neural voices via `edge-tts`, ElevenLabs (user will create a
  key), Kokoro (local, model downloaded on demand). Plus macOS `say` as the always-available fallback.
- Claude writes the narration script in the skill, from `doc.md` + the user's notes. No LLM API call.
- Two looks, chosen per video: a clean typeset stage (default) and the workbench viewport (`--chrome`).

**Rulings made while planning:**
1. **Rust renders, Python orchestrates.** edge-tts and Kokoro are Python-only, so the pipeline is a
   `uv` project (`tools/shorts/`) that calls a new Rust binary for frames. The Rust side never does
   networking.
2. **Text is drawn by egui, not ffmpeg.** The user's ffmpeg has libx264/aac but no `drawtext` or
   `subtitles` filter. Drawing in egui also keeps the app's palette and fonts.
3. **Scene = one narration unit.** TTS runs once per scene (natural prosody). The scene's caption is
   its narration text, shown while its audio plays. No word-level karaoke in v1.
4. **The renderer takes a storyboard JSON** with fixed scene lengths (from the audio durations) and
   writes a silent `video.mp4` plus `contact.png` (one frame per scene) so Claude can check the look
   by reading a PNG. Python muxes narration (and optional music) into `short.mp4`.
5. **Physical size is exact.** `--size shorts` = 1080×1920, `square` = 1080×1080, `landscape` =
   1920×1080, or `WxH`. The renderer runs egui at `physical / scale` logical points (default scale 2,
   so a Short is a 540×960 layout with thick enough strokes) and asserts the rendered image equals the
   requested size before piping it to ffmpeg.
6. **Output folder:** `generated/<YYYY-MM-DD_HHMM>-<tool-id>/` (gitignored). Everything lands there.
7. **Scene `state`:** a scene may set formula parameters through `Formula::load_state` (e.g. Lorenz
   `rho` 28 → 15 mid-video). Reuses the sheet-state machinery; no new per-tool code.

## Architecture

```
script.md ──► formula-shorts build ──► TTS per scene ──► scenes/NN.wav + durations
 (Claude)        (Python, uv)            │
                                         ├─► storyboard.json ──► formula-render (Rust) ──► video.mp4, contact.png, thumbnail.png
                                         └─► narration.m4a (concat + pad + loudnorm [+ music]) ──► ffmpeg mux ──► short.mp4
                                                                                    + captions.srt, post.md, build.log
```

### 1. Rust renderer: `tools/capture` becomes lib + two bins

`tools/capture/src/lib.rs` takes the reusable harness code from today's `main.rs`: `DT`-style
stepping, `board()` (loads the Pathfinding lab maze into `ToolEnv`), `Stage`, `render`, `crop`,
`warmup`. `src/main.rs` (README media, `formula-capture`) keeps its behavior. New
`src/bin/render.rs` (`formula-render`):

- `formula-render tools` → JSON array of `{id, name, category, alias, summary, equations: [text],
  state_params: [..], min_size}` built from `formulas::TOOLS` by making one instance each. Python
  and the skill use it to validate ids and show Claude the parameter names.
- `formula-render <storyboard.json>` → reads the storyboard, renders every frame, pipes raw RGBA to
  `ffmpeg -f rawvideo -pix_fmt rgba -s WxH -r FPS -i pipe:0 -c:v libx264 -preset medium -crf 18
  -pix_fmt yuv420p -movflags +faststart video.mp4`, saves `contact.png` (scene midpoint frames in a
  row, scaled to 270 px wide each) and `thumbnail.png` (frame at `thumbnail_at` seconds, default the
  first scene's midpoint). Prints progress every second of video.

Storyboard (serde, `#[serde(default)]` on every optional field):

```json
{
  "tool": "lorenz", "width": 1080, "height": 1920, "fps": 30, "scale": 2.0,
  "theme": "dark", "chrome": false, "lead_in": 0.5,
  "title": "Lorenz attractor", "kicker": "Chaos & Dynamical Systems",
  "footer": "Formula  ·  github.com/VachaganGrigoryan/Formula",
  "thumbnail_at": 2.0,
  "scenes": [
    {"heading": "One tiny difference", "caption": "Two paths start 0.00001 apart...", "seconds": 4.6,
     "state": {"paths": 2}, "equations": true},
    {"heading": "Then they part", "caption": "...", "seconds": 5.1}
  ]
}
```

Frame layout (logical points, clean mode), top to bottom inside 6% side margins, with the top 8% and
bottom 18% kept free for the platforms' own UI:
1. Title (tool name, proportional ~30 pt, `ink`), kicker under it (~14 pt, `muted`).
2. Equations: `Formula::equations()` laid out with `MathText::layout(palette, 17)`, at most three
   lines, each shrunk to fit the width (same rule as `fit_text`). Hidden when the scene sets
   `equations: false`.
3. Stage: full content width, height `Formula::stage_height(width)` capped at 52% of the frame
   (then the width shrinks to keep the aspect), centered in the remaining band, on a `card`
   rounded rect. `Formula::paint(painter, stage_rect, palette, 1/fps)` every frame.
4. Caption block: scene `heading` (~20 pt, `x` accent) and `caption` (~22 pt, `ink`, wrapped),
   fading in and out over 0.25 s at scene edges.
5. Footer (~12 pt, `muted`).

Chrome mode (`chrome: true`): the stage band hosts a `Workspace` exactly like `capture::viewport`
(tool placed at `Pos2::ZERO`, camera centered, rulers/minimap off), shown in
`ui.new_child(UiBuilder::new().max_rect(stage_rect))` since `Workspace::show` sizes itself from
`ui.max_rect()`. The viewport's own title tab appears, so the layout's title shrinks to the kicker
only. Scene `state` goes through `ws.board.get_mut(uid).formula.load_state`.

Per frame: `t += 1/fps`; when `t` crosses a scene boundary apply that scene's `state`; after the last
scene ends, stop. Frame count = `round((lead_in + Σ seconds) * fps)`. Unit tests (no GPU) cover:
storyboard parsing with defaults, logical-size math (1080×1920 at 2.0 → 540×960; odd sizes rejected
with a clear error), the layout function (rects fit inside the frame, stage respects min_size and the
52% cap, safe bands kept), and scene lookup by time. A GPU smoke test is manual (see Verification).

### 2. Python orchestrator: `tools/shorts/` (uv project, Python ≥ 3.11)

`pyproject.toml` with console script `formula-shorts`, deps: `edge-tts`, `httpx` (ElevenLabs REST),
`kokoro-onnx` + `soundfile` (Kokoro), `pyyaml` (front matter). Dev: `ruff`, `pytest`. Package
`src/formula_shorts/`:

- `script.py`: parses `script.md`. YAML front matter (`tool`, `title`, `size`, `theme`, `chrome`,
  `voice`, `provider`, `music`, `post: {title, description, hashtags}`) then scenes: each `## Heading`
  starts a scene; a line `state: {json}` sets parameters; `equations: false` hides them; the remaining
  paragraphs are the narration. Validates: tool id exists (via `formula-render tools`), 1–8 scenes,
  ≤ 45 words per scene, total ≤ 220 words (≈ 80 s at speech rate), state keys ⊆ `state_params`.
- `tts/`: `base.py` (`Provider.synthesize(text, voice, out_wav)`, `voices()`, `ready()`),
  `edge.py` (`edge_tts.Communicate(text, voice).save(mp3)`; default voice
  `en-US-AndrewMultilingualNeural`), `elevenlabs.py` (REST `POST /v1/text-to-speech/{voice_id}`,
  header `xi-api-key` from `ELEVENLABS_API_KEY`, `model_id` default `eleven_multilingual_v2`, voice
  resolved by name through `GET /v1/voices` and cached in `~/.cache/formula-shorts/`), `kokoro.py`
  (`kokoro_onnx.Kokoro(model, voices).create(text, voice="af_heart", lang="en-us")` → wav 24 kHz;
  model files `kokoro-v1.0.onnx` + `voices-v1.0.bin` downloaded by `formula-shorts setup kokoro`
  into `tools/shorts/models/`, gitignored, with size checks), `say.py` (`say -v Samantha -o
  out.aiff`). `auto` picks the first ready provider: elevenlabs (key set) → kokoro (model present)
  → edge (network) → say. Every provider output is normalized to 48 kHz mono wav with ffmpeg.
- `audio.py`: durations via `ffprobe -show_entries format=duration`; concat with `apad=pad_dur=0.35`
  per scene and `lead_in` silence; `loudnorm=I=-16:TP=-1.5`; optional `--music file` mixed at
  −18 dB with a 1.5 s fade-out; encodes `narration.m4a` (aac 160k).
- `storyboard.py`: builds the JSON from script + durations + CLI flags (`seconds` = audio + 0.35).
- `render.py`: runs `cargo run --release --manifest-path tools/capture/Cargo.toml --bin
  formula-render -- storyboard.json` (or `FORMULA_RENDER` env for a prebuilt binary).
- `mux.py`: `ffmpeg -i video.mp4 -i narration.m4a -c:v copy -c:a copy -shortest short.mp4`.
- `outputs.py`: folder `generated/<YYYY-MM-DD_HHMM>-<tool>/`, writes `captions.srt` (one cue per
  scene from the timings), `post.md` (title, description, hashtags from front matter), copies
  `script.md`, keeps `scenes/`, `storyboard.json`, `build.log`.
- `cli.py` (argparse): `tools`, `voices [--provider]`, `setup kokoro`, `build <script.md> [--size]
  [--provider] [--voice] [--theme] [--chrome] [--music] [--scale] [--fps] [--out DIR] [--dry-run]`.
  `--dry-run` skips TTS, estimates `seconds = words / 2.6 + 0.6`, and renders only `contact.png`
  (renderer flag `--contact-only`) so the look can be checked in seconds.

Tests (pytest, TTS and subprocesses mocked): front-matter and scene parsing including `state:` and
`equations: false`, word-budget errors, storyboard assembly and defaults, provider `auto` order under
different env/filesystem states, ffmpeg argument construction for concat/loudnorm/music, srt text,
output folder naming with a fixed clock. Gate: `uv run ruff check . && uv run ruff format --check .
&& uv run pytest -q` inside `tools/shorts`.

### 3. Skill: `.claude/skills/formula-short/SKILL.md` (+ `references/script-guide.md`)

Checked into the repo so it travels with it. Frontmatter `name: formula-short`, description
"Make a narrated YouTube/Instagram Short of a Formula tool from its id and optional notes". Steps:
1. Resolve the tool: run `formula-shorts tools`, match the user's words to an id (ask if ambiguous).
2. Read `assets/content/<id>/doc.md` (Overview, Intuition, Applications) and the user's notes.
3. Write `generated/drafts/<id>-script.md` following `references/script-guide.md`: hook in the first
   sentence, 4–6 scenes, ≤ 30 words each, 90–140 words total, spoken English (write "sigma", "x
   squared", no Greek letters or symbols for the TTS), a `state` only from `state_params`, and a
   `post:` block (title ≤ 60 chars, description, 3–6 hashtags).
4. Build: `--dry-run` first, read `contact.png`, fix layout problems (too-long captions), then the
   full build with the provider/voice the user asked for (default `auto`).
5. Report the folder, duration, provider used, and offer a re-voice or a different look.

## Risks and how the plan handles them

- **kittest render size vs. pixels_per_point**: settled by the spike in step 1 before any layout code.
- **kokoro-onnx / edge-tts APIs drift**: both are wrapped behind `Provider`; failures fall through
  `auto` to the next provider with a one-line reason in `build.log`. Verify exact call signatures
  against the packages' READMEs when implementing step 8 (Context7 quota is exhausted this month).
- **ElevenLabs free quota (~10k chars/month)**: the script validator shows the character count and
  the CLI prints the estimated credits before calling the API.
- **Render time**: 1350 frames at 1080×1920 through a pipe, no PNGs on disk; expect about one to two
  minutes per Short on this Mac. `--dry-run` keeps the iteration loop to seconds.
